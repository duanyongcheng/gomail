# M2 frontend implementation evidence

Date: 2026-11-02. Scope: delegated frontend integration only. The integration coordinator owns the combined Go/build/packaged acceptance results; this report does not claim those results.

## Implemented paths

- `src/components/AccountSetup.tsx`: reachable Gmail, IMAP/SMTP, POP3/SMTP and Microsoft provider selection. Gmail remains the default and uses its existing OAuth/start-sync path. Protocol and Microsoft account creation invalidate local account queries without enabling automatic sync. Credential forms mount only after explicit provider selection.
- `src/features/settings/ProtocolAccountForm.tsx`: typed `AccountService.add`, `test`, `protocolSettings` and `saveProtocol`; write-only passwords; blank edit passwords preserve backend credentials; saved safe endpoint values include no password. Revision accompanies edits so backend CAS rejects stale settings. Incoming and SMTP credentials/authentication remain independent. SMTP defaults disabled for receive-only accounts.
- Protocol transport settings expose verified TLS and mandatory STARTTLS/STLS, bounded port inputs, username and explicit additional CA PEM trust scoped to each endpoint. No plaintext or blanket invalid-certificate option exists. Additional CA consent explains retained hostname verification.
- IMAP selected folders can be edited by exact server names and chosen from cached folder IDs/names. POP3 explicitly explains unavailable flag/folder/move/trash operations and independent SMTP sending requirements.
- `src/features/settings/MicrosoftAccountForm.tsx`: typed public-client authorize/status/cancel flow; client ID, validated-backend tenant/audience policy, separate Graph/IMAP/SMTP selection; no pasted token or client secret fields. Graph is visibly experimental. Resource authorization is distinguished from protocol-login verification and recipient delivery. Isolated outgoing authorization state is visible with reauthorization available while receive status remains independent.
- `src/features/settings/ProxyTab.tsx`: actual typed network read/save for global HTTP CONNECT/SOCKS5 policy. Protocol edit forms expose inherit/direct/custom per-account policy. App versus browser routing is explained. Failed initial reads cannot overwrite settings. Global policy changes do not activate sync in the UI.
- `src/features/settings/GmailNetwork.tsx`: explicitly opened Gmail account connection routes panel using safe typed `AccountService.accountNetwork/setAccountNetwork`; inherit/direct/custom HTTP CONNECT or SOCKS5 settings scoped to account ID, stable account keys, failed-load preservation and stale-response suppression. No credentials appear in the route DTO.
- `src/features/settings/ProtocolFolders.tsx`: typed folder management read/refresh/create/rename/delete/dismiss. System folders are not selectable for rename/delete. Destructive deletion and dismissal require explicit confirmation. Pending unresolved operations disable further writes while refresh remains available. No automatic replay follows an uncertain receipt.
- `src/features/settings/AccountsTab.tsx`: reachable protocol editing and stored-credential tests; isolated connection/Microsoft/folder sections; busy close/section guards, keyboard focus trapping, stale account test result suppression. Existing Gmail preferences/signatures panel stays in place.
- `src/lib/mailCapabilities.ts`, message action toolbar/rows/list/mark-all controls and central mutation helpers: explicit `modify_flags:false` blocks unsupported actions including keyboard/batch paths before native mutation. Missing legacy fixture capabilities retain compatibility. Folder management is separately capability-gated. POP3 remote changes remain unavailable.
- `src/lib/platform/commands.ts`: actual legacy adapters only for add-account and IMAP/POP3/stored connection tests. Direct typed APIs above do not falsely implement old proxy/token invokes. `src/lib/availability.ts` reflects working typed proxy/Microsoft services and actual protocol command adapters.
- `scripts/generate_commands.py`, `src/lib/platform/manifest.ts`, `docs/parity.md`: 145 legacy commands, 58 implemented adapters. Generator now recognizes digits in names (the old regex omitted `test_pop3_connection`). `advanced_search` remains deferred to M3. Parity explains direct typed services versus pending legacy invoke names.
- `src/lib/ipc-types.ts`: additive optional folder-management capability mirror.

## Remaining boundaries and manual acceptance

- These are component/adapter checks with local mocks. Provider protocol, vault/reopen, migrations, actual durable barriers, TLS/proxy fixtures, OAuth fixtures, full gate and signed package execution belong to the coordinator/provider evidence and are not established by these UI tests alone.
- Dedicated-account consent, Microsoft native-client registration/tenant SMTP AUTH configuration, real system keyring behavior and recipient-side delivery/Bcc acceptance remain manual acceptance. No manual evidence was changed to imply success.
- Old proxy invoke names remain unavailable; the actual global and Gmail/protocol/Microsoft per-account routes use typed implementations. Old XOAUTH2 refresh-token UI and identity preview invokes are not enabled or presented as substitutes for public-client authorization.
- Cached folder choices require prior folder discovery; users can enter exact selected IMAP remote names before the first sync. Folder management provides explicit remote refresh for capable accounts.
- The original November 2 panels used English defaults. The November 3 continuation adds English/Chinese labels, help, status and confirmation text through the existing i18n resources; service values and backend error diagnostics are unchanged. Current evidence is in `m2-review-validation.md`.
